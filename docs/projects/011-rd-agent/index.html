TWO WORK MODES

两种工作方式，许多具体场景

“两种”指解决问题的方式，并不表示这个库只有两个功能。具体应用仍要按数据、目标和评价方式选择或适配。

RD-Agent 本身不是训练好的基础模型。它调用外部大模型提出方案和编写代码，再调度真实程序执行。关键价值是让下一次尝试依据上一次的实验结果，而不是只生成一次答案。

A / COPILOT · 已有方法的实现

论文、研报 → 可运行代码

适合你已经找到论文或明确的算法描述，想看它怎样被实现。论文检索通常要先由你或其他工具完成；通用模型入口接收 PDF 文件或 PDF 链接，具体参数以所用版本为准。

读取 PDF→提取规格→生成代码→运行修复
输入
论文或报告、模型结构、公式；还需大模型接口与执行环境。
反馈
通用模型会检查样例输入、形状和运行错误；金融因子场景还可以结合回测反馈。
输出
模型或因子代码、检查结果、实现记录；可运行不等于论文效果已复现。
B / AGENT · 围绕目标自主实验

数据集、指标 → 多轮候选方案

适合有数据、目标和可重复评分方式的问题，例如预测、量化因子研究或基准驱动的微调。

提出假设→编写代码→训练评估↺反馈迭代
输入
训练/验证数据、任务说明、目标指标、基线与运行预算。
反馈
训练或回测程序产生的分数、错误、耗时和历史实验记录。
输出
多轮特征/模型方案、代码、指标和实验轨迹；提升与否由评估结果决定。

还要分清三个维度

官方将 Copilot 和 Agent 视为两类主要角色，同时把模型实现与数据构建视为两类研发对象。它们可以组合使用，不是四套互不相干的产品。

01 / 角色

谁决定下一步？

Copilot 主要跟随人给出的论文、报告或方向；Agent 更主动地依据实验反馈提出新方案。

02 / 研发对象

改进什么？

可以实现或优化模型，也可以构建数据、特征或量化因子；微调任务还涉及数据处理和训练配置。

03 / 领域

在哪个问题里做？

官方已有金融、数据科学、论文模型和大模型微调等场景；3D 人物等领域需要自定义适配。

论文和数据集只是常见入口，不是互斥的分类；同一任务可以先由人指定方向，再让 Agent 迭代探索。部分循环有人工修改假设或反馈的接口；并行探索、命令行和界面属于调度或操作方式。

数据集路径里，谁在“分析数据”？

大模型依据任务说明、样本或数据概况、已有实验反馈设计方案；生成的 Python 程序读取数据、训练模型并计算指标。训练得到的模型参数来自训练算法对数据的计算，并非大模型凭文字直接写出。

① 大模型：设计例如“预测客户流失”，提出清洗、特征工程和模型候选。
② 训练程序：学习读取训练数据，执行特征处理和模型拟合，产生模型参数或预测。
③ 评估程序：打分在固定验证集计算 AUC 等指标；RD-Agent 保存结果并组织下一轮。
前提与边界：“更好”必须尽量转成可检验标准。像“做一个高质量 3D 人物”需要先明确输入、人物格式、几何/纹理/动画质量及评价方法；目前不是把任意论文或愿望交给 RD-Agent 就能自动得到成品。
实际运行条件：官方当前 README 标明仅支持 Linux；多数场景需要 Docker，还需配置聊天模型和嵌入模型接口。训练或回测会消耗时间与算力，尤其是微调任务。本站网页仅用于说明与模拟，不会运行上游框架。查看官方准备要求 ↗

VALUE FOR YOUR PROJECTS

放进你现有的项目，价值在哪里？

这部分是结合本研究仓库已有项目的应用判断，跨项目接口尚未接入或实测。

01 / VOICE

语音工具链：最适合先试

为 Voicebox 与 WhisperLiveKit 准备固定中文样本，比较词错率、延迟和资源消耗。建立可靠评分后，再探索数据或模型改进。

02 / MEDIA

内容生产：先定义质量

Jellyfish 与 video-use 涉及分镜、镜头和剪辑。可以记录耗时、失败率等客观指标；画面与叙事质量仍需要人工评价。

03 / DECISION

优先把它当作研发方法

先固定数据、基线与评价规则，再决定是否接入 RD-Agent 自动探索。当前页面没有连接这些项目，也没有运行任何模型。

04 / 3D AVATAR

3D 人物：先确认完整目标

从文字或单张图像生成、网格与纹理、骨骼和动画是不同问题。可先对照相关论文与公开实现；RD-Agent 目前没有现成的 3D 人物完整工作流，若要自动迭代需另建执行与质量评价。

适合的第一个小实验：选 30–50 段有人工转写的中文音频，测一条稳定基线；再比较不同处理方案的词错率、延迟和成本。结果可复查后，才有持续自动优化的基础。

后期值得回顾，但要带着具体问题回来

针对你目前“理解论文”和“生成 3D 人物”的需求，先用论文原文、作者公开代码和普通大模型拆解方法。RD-Agent 的优势出现在需要反复改代码、真实运行并比较结果的时候；为了一次性读懂论文而搭建整套环境，投入通常不划算。

现在 · 学习

把论文变成可理解步骤

梳理目标、输入输出、核心公式与实现条件；需要看代码时再试 Copilot 的初版实现。

稍后 · 小实验

用一个可评分任务验证价值

例如中文语音识别：固定样本、基线、词错率、延迟与成本，运行少量迭代并人工检查。

再决定 · 接入

只在收益超过成本时扩展

确认结果可复现、预算可控，再为语音或 3D 自建执行和评价环节。

重新尝试清单：明确目标、可用数据或论文、可运行基线、固定评价规则、算力与 API 预算、人工验收人。缺少可靠评价时，先建设评价方法。

EXTEND THE FRAMEWORK

可扩展的三个方向

以下是基于现有接口提出的实践方向，不代表上游已经提供这些业务集成。

01 / SCENARIO

自定义业务场景

接入你自己的数据、任务描述、实验运行环境和评价器，让假设与反馈围绕真实业务目标展开。

02 / EVALUATION

多目标评估

同时比较质量、速度、成本和稳定性，并固定测试集，减少数据泄漏或只追逐一次高分的风险。

03 / KNOWLEDGE

积累团队经验

保存假设、代码、失败原因与人工判断，让后续探索能利用过去真正有效的经验。

你的任务，适合自动化探索吗？
