social-auto-upload 让用户先在项目打开的浏览器中登录，再保存登录状态；后续依据创作者网页的上传框、输入框和按钮等元素，自动上传素材、填写信息并提交。

仓库列有 11 个可上传视频的平台：其中 9 个统一 CLI 平台走浏览器网页操作；Bilibili 委托 biliup，TikTok 保留为独立旧示例。它适合承担个人 IP 内容做好之后的重复分发；统一命令行每次选择一个平台。

02 / PUBLISHING ROUTES

11 个平台怎么发布？

下列是仓库代码实际采用的接入路径。点击平台可看登录、上传、提交和已知边界；“支持”不等于已在你的账号上完成实测。

核对 CLI 覆盖 ↗
9统一 CLI → 浏览器网页5 个使用 Patchright，4 个仍使用 Playwright
1统一 CLI → biliupBilibili：由外部程序处理登录与上传

Patchright / Playwright 是控制浏览器的程序库，不是浏览器本身。本项目另行安装并启动 Chromium，可显示窗口或在后台无窗口运行。各平台分别登录、保存状态；脚本复用状态后打开创作者后台，选文件、填表、点击发布。定时是填写平台提供的预约控件。

抖音Patchright · 创作者网页视频＋图文 · CLI / Skill · 定时

登录：打开创作者中心，由你扫码；保存浏览器状态，之后加载状态并检查能否进入上传页。

发布：视频经文件框上传，填标题、描述、话题，可设置封面、合集和商品信息；图文切换到图文发布页，上传多张图片。定时在网页上选择“定时发布”并填写时间。

判断与边界：点击发布后以跳转内容管理页作为程序成功信号。视频上传在未给自主声明时会默认选“内容由AI生成”，与 CLI 帮助不一致。

上传与发布源码 ↗定时控件 ↗

Bilibili外部 biliup 程序视频 · CLI / Skill · 定时

登录：在本地交互终端运行 biliup 登录并扫码；账号文件交给 biliup 使用，不走本项目的浏览器表单路径。

发布：统一 CLI 把视频、标题、描述、分区 tid、标签、封面交给 biliup upload；定时转换为 --dtime 时间戳。首次可自动下载 biliup，后续会检查更新。

判断与边界：以 biliup 进程退出码为程序结果；其底层上传通道由 biliup 版本决定，不能把它当作本项目的 Patchright 发布流程。

CLI 调用源码 ↗biliup 运行封装 ↗

小红书Patchright · 创作者网页视频＋图文 · CLI / Skill · 定时

登录：创作者后台扫码，保存浏览器状态；上传前重新访问后台，确认没有跳回登录页。

发布：视频与图文分别进入对应上传页，选择文件，填写标题、正文、话题；视频可设置封面。定时打开平台页面开关、填日期，再提交定时发布。

判断与边界：以进入发布成功页判断脚本完成；仍需到账号内容管理页确认审核与实际可见性。

视频与图文 uploader ↗CLI 用法 ↗

快手Patchright · 创作者网页视频＋图文 · CLI / Skill · 定时

登录：创作者后台扫码并保存状态；上传前检查登录态是否仍有效。

发布：视频通过文件选择器上传，填写一个描述编辑框和话题，可设封面、合集；图文切到图文页上传多张图片。定时通过平台日期控件设置。

判断与边界：以跳转到内容管理页判断提交。视频的 --title 只是描述框的备用文本；图文标题虽能传入 CLI，但代码没有将其写入独立标题栏。

视频号Patchright · 视频号助手网页视频 · CLI · 定时 / 草稿

登录：微信扫码进入视频号助手，保存浏览器状态；再次上传时检查是否跳回登录页。

发布：上传视频，填写描述、话题和短标题，可设置横竖封面、合集、草稿或平台原生定时。提交后根据离开创建页或按钮变化判断。

百家号Playwright · 创作者网页视频 · CLI · 无定时

登录：百度账号扫码后保存浏览器状态；上传前验证账号仍可进入后台。

发布：在网页选视频、填标题、上传横版封面、选合集，再点击发表；跳转到内容页等地址时视为已提交。

03 / MECHANISM

它怎样完成一次发布？

以抖音等平台为例：先登录并保存浏览器状态，再让程序带着这个状态操作创作者网页。

一句话看懂

人工登录 → 保存登录态 → 新浏览器会话恢复 → 按网页元素上传与发布

保存的是浏览器登录状态文件，通常含 Cookie 和站点的本地存储。Cookie 用来证明“这是已登录的账号”；上传素材、填写信息和点击发布，靠自动化浏览器完成。各平台分别保存自己的账号状态。

你正在看的能力地图只是说明页；真正执行发布的是原仓库的 sau 命令和各平台 uploader。

你刚才问的关键问题

手动登录后，程序究竟怎样“接着操作”？

会复用这次登录获得的身份，但通常会打开新的浏览器会话。它把项目登录窗口中的 Cookie 等站点状态保存为 JSON；发布时再加载到新的 Chromium 浏览器上下文。平台若仍接受该会话，就会显示同一账号的创作者后台。

在项目打开的窗口登录可以延续

运行该项目的登录流程并扫码或手动登录，程序才会保存相应账号状态。

只在日常 Chrome 登录默认不会带入

项目一般启动自己的 Chromium；你日常浏览器的 Cookie 不会自动进入它的账号文件。

四个角色：Patchright / Playwright 是浏览器控制库；Chromium 是实际运行网页的浏览器；Cookie 等登录状态用来表明账号身份；脚本按网页元素定位上传框、输入框和按钮，再自动选择文件、填表和点击发布，由创作者网页向平台服务器发出请求。登录状态过期或遇到二次验证时，需要再人工登录。

源码和文档：打开浏览器并保存状态 · 新会话恢复并上传 · 浏览器状态格式 · Patchright 项目

网页元素怎样变成发布动作

它按已写好的定位规则操作页面

以抖音视频为例，脚本进入上传页，按 CSS 选择器查找文件输入框；也会按按钮文字、元素角色或页面结构定位控件。找到后把本地视频交给文件框，填写标题和描述，点击平台页面的发布按钮。浏览器加载的网页处理这些动作，再向平台服务器发送上传与提交请求。

脚本还会等待上传完成、弹窗关闭或页面跳转，再判断是否提交。平台改版后，如果元素或流程改变，对应的定位规则和判断逻辑就需要维护。

定位元素→选择文件与填表→点击提交→检查页面反馈

核对依据：抖音上传与元素定位 · 提交与页面结果 · 定位器文档

  1. 01

    准备账号

    在项目打开的浏览器中人工登录。程序检查会话，并把 Cookie 等状态保存到本地账号文件。

  2. 02

    选择平台

    sau 接收平台、账号、素材、标题、描述等参数，转给对应的 uploader。

  3. 03

    操作后台

    打开新浏览器会话并恢复登录状态；Patchright 或 Playwright 驱动 Chromium，查找上传框、填表，并在可用时设置平台定时。

  4. 04

    提交与核验

    程序等待上传、点击发布并判断页面结果。实际作品状态仍应到平台后台复核。

存在哪里

登录态按平台和账号保存在本地 cookies/*.json。虽然目录名叫 cookies，文件实际保存浏览器状态，应按账号凭据保管；失效后需重新登录。

平台例外

B站通过 biliup 执行上传；TikTok 使用旧 Chrome 示例，尚未接入 sau。

关于“多平台”

统一 CLI 提供的是多个平台入口。要连续分发，需依次调用，或再接一层外部调度。

实现依据：扫码后保存登录态 · 上传时恢复登录态 · 账号文件 · 浏览器上传 · 定时控件 · B站调用

04 / FOR YOUR IP

对你建立个人 IP 的价值

它最适合放在“内容已经做好 → 稳定分发”这一段。你能把同一主题的素材有计划地送到几个平台，把手工上传的时间留给创作与交流。

你决定定位与选题面向谁，表达什么
工具承担重复发布上传、填表、排期
你继续做反馈与迭代评论、数据、下轮改进

工作区中的 RVC 项目偏向声音制作；这个项目偏向成品内容的分发。两者可以处在同一条创作链的不同环节。

建议的接入顺序

  1. 1
    先定一个内容主题

    明确目标受众，以及视频或图文的基本形式。

  2. 2
    选两个平台试发

    根据平台调整标题、封面和表达，观察哪类内容有效。

  3. 3
    流程重复后再自动化

    先用一个账号、一条内容试跑，核对发布结果，再扩大范围。

判断标准：重复上传与排期，是否已经明显占用你的创作时间。

05 / BOUNDARIES

使用前，先看这些边界

01

页面变化会影响脚本

上传流程依赖创作者后台的页面元素。平台改版、登录态失效或二次验证，都可能使任务中断。

02

旧版 Web 不是主线

仓库正围绕 CLI、Skill 与 Patchright 重构。作者明确表示历史 Web 代码不保证可直接运行。

03

平台能力需要实测

上面的矩阵来自项目自述，不是对你的账号逐一跑通后的结果。正式发布前需小范围验证。

!

代码默认值影响实际发布

先核对 AI 内容与原创声明

抖音视频的 CLI 帮助称省略 --declaration 不设置，但上传代码会默认选“内容由AI生成”。视频号、百家号、支付宝生活号与微博的视频流程也会尝试选择 AI 内容声明；微博还固定选择“二创”。这些操作可能因页面变化而未生效。发布自己的原创内容前，应按真实情况逐平台检查。
