010 / AI SHORT DRAMA STUDIO

从剧本到镜头素材的
短剧生产工作台。

Jellyfish 以分章剧本为入口，组织剧本拆解、分镜与导演提示、角色和场景复用、人工确认及图片／视频生成。它主要交付结构化制作资料与单镜头素材，供后续审片和剪辑使用。

ONE-PAGE GUIDE

一张图看清入口、处理、出口与边界

顺着图中箭头阅读：剧本由文本模型转成分镜候选；创作者确认设定与镜头；工作台再调度外部图像和视频模型，保存结果与任务上下文。

INPUT → OUTPUT

入口是剧本，出口是制作资料和镜头素材

01 / 输入

分章或分集剧本

拆镜头接口接收完整剧本文本。项目还可补充角色、场景、服装、风格和参考图，并配置要调用的文本、图片、视频模型。

小说段落可作为文本提交，但现有拆镜头提示词以剧本为对象；正式制作建议先完成小说改编。

02 / 输出

数据、媒体与任务记录

数据包括分镜、对白、实体关联、候选确认和提示词；媒体包括参考／生成图片及单镜头视频；任务中心保留进度、结果与项目上下文。

完整自动剪辑、配音、字幕与成片导出需单独核验。

PRODUCTION FLOW

支持的五类处理

01 / 理解

拆镜头与提取要素

文本模型提取镜头、角色、场景、道具、服装和对白，另有剧本优化、精简、一致性检查与专项分析。

02 / 导演辅助

设计镜头画面

支持修订镜头信息；帧提示词考虑景别、机位、运镜、动作、相邻镜头和导演指令，生成首帧、关键帧与尾帧的画面描述。

03 / 人工确认

准备镜头、复用资产

接受、忽略或关联候选资产与对白；复用已确认的角色和场景，管理关键帧与参考图，并检查镜头是否准备好。

04 / 模型生成

出图与镜头视频

预览视频提示词，执行单镜头或批量预检查，向配置好的图像／视频服务发起生成任务，再将结果回写镜头。

05 / 制片管理

跟踪长耗时任务

统一查看文本、图片、视频任务的状态、进度、耗时和结果；支持取消并返回对应项目、章节或镜头。

HOW IT WORKS

模型生成内容，工作台组织流程

剧本文本→文本模型结构化提取→人工确认与资产关联→图像／视频模型生成→结果回写与追踪

后端以 FastAPI、SQLAlchemy、Pydantic 和 LangChain 系列组件管理接口、数据与文本模型输出；Celery / Redis 承担异步任务，Docker Compose 方案配置 MySQL 与 S3 兼容存储。前端使用 React、TypeScript、Vite。模型由外部 Provider 提供，Jellyfish 不随仓库附带自研基础视频模型。

WHY IT MATTERS

对我：补上剧本到镜头素材这一段

当内容需要多个镜头、反复出现同一人物或批量制作时，统一实体库、人工确认和任务追踪比单次生成更有价值。

连续短剧

复用人设、场景和参考图，减少反复描述与跨镜头漂移，最终效果仍需审片。

批量制片

按镜头跟踪准备状态、生成结果和返工位置，方便团队协作与成本复盘。

现有工具链

可探索将镜头片段交给 008 video-use 剪辑，再由 002 social-auto-upload 发布；跨项目集成尚未验证。

BOUNDARIES

采用前要验证的三件事

  1. 小说改编：目前明确的主入口是剧本；整本小说到分集剧本需要前置流程。
  2. 导演质量：系统可辅助镜头与画面提示词，节奏、表演和镜头取舍仍需创作者决定。
  3. 完整交付：仓库介绍提到导出，但自动剪辑、配音、字幕和成片效果应以真实样片核验；同时记录模型费用与失败重试。
