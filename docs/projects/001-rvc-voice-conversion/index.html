研究摘要 · 001

能力、实现原理与对我的意义

源库：Retrieval-based-Voice-Conversion-WebUI

能力

把已有讲话或歌声转换成目标声线，支持离线批量转换、实时变声和目标声线训练，并提供人声分离等辅助功能。

实现原理

HuBERT 提取发音特征，RMVPE 等方法估计音高，RVC 目标声线模型生成新波形；可选特征检索减轻原声残留，多个模型通过同一套程序协作。

对我的意义

可作为自建软件的换声模块，也可借鉴预训练模型、目标微调与检索协作的方法。当前以理解为主，无需立即安装；实际音质、相似度和设备延迟需日后验证。

讨论汇总 · 先看结论

我们现在理解了什么？

从声音是什么，一直追到核心模型、运行环境与使用价值，把容易混淆的概念串起来。

一句话概括

RVC 把发音特征提取、音高估计与目标声线生成组织成换声流程：输入已有录音，输出尽量保留内容和节奏、具有目标声线特点的新音频。

本地或服务器描述计算发生在哪里；多个模型如何协作，才是这项能力的实现方式。
01 / 声音基础

录音是一条波形，信息交织其中

振幅主要影响响度，基频主要影响音高；谐波比例、噪声及时间变化共同影响音色。谐波本身也有频率和振幅。内容、音高、音色共同体现在波形中，并没有各自独立保存成音轨。

提取所需线索，再生成新的波形

RVC 提取按时间排列的发音特征，以及可选的音高走势，再让学过目标声线的模型生成声音。它不必先把录音转成文字；信息分离是近似的，转换也可能影响咬字、气声和细节。

01 / 从物理声音到数字录音

声音，是随时间传播的压力变化

以空气中的声音为例：物体振动，让周围空气交替压缩、变稀，这种变化向外传播，传到耳朵后引起鼓膜振动。我们由此听到声音。

  1. 声源振动例如扬声器振膜
  2. 空气压力变化声波传到麦克风
  3. 麦克风变成电信号电信号随声音变化
  4. 采样成一串数字电脑记录每个时刻的数值
电脑实际拿到什么？

一条数字波形。把这些数值按时间画出来，横轴是时间，纵轴是信号大小。词句、音高和音色的信息都共同体现在波形里，需要进一步分析才能提取。

基础资料：OpenStax：声波、MDN：数字音频波形。

02 / 同一段声音的不同特征

音高、音量、音色，分别在说什么？

音高：听起来高还是低

对有明确音高的声音，主要与基频有关。每秒重复越快，通常越高。220 Hz 表示每秒重复 220 次。

例子：同一个人从低音唱到高音。这里的音高，就是常说的“音调高低”；语调则是一句话里音高起伏的走向。

音量：听起来响还是轻

波动幅度更大，通常更响。但听觉响度也受频率、持续时间和听音环境影响，不能只看波形高度。

例子：同一个音，小声说或大声说。

音色：声音有什么质感

即使音高、响度接近，两种声音仍能听出区别。这与各频率成分的比例、起音衰减、噪声等有关。

例子：钢琴与小提琴奏同一个音；两个人唱同一个“啊”。
为什么“音色”更复杂？

真实人声会同时含有多种频率。例如基频是 220 Hz 时，还可以包含 440、660 Hz 等谐波（整数倍频率），这些属于泛音。它们各有多强，加上气息噪声和随时间变化的发声方式，共同影响音色。改变音高，只改变了其中一个方面。

03 / 把这些概念放回人声

声带提供振动，声道塑造声音

发出有声的“啊”时，肺部气流驱动声带振动，产生包含基频与谐波的声音。声音经过咽喉、口腔等部位，不同频率被不同程度地增强或减弱，形成我们听见的人声。

  1. 肺部气流提供发声动力
  2. 声带振动产生基频与谐波
  3. 声道共鸣与发音动作舌头、嘴唇等改变声音
  4. 最终人声同时带有内容和个人特征

这些共鸣在频谱中形成的突出区域常称为共振峰。嘴形、舌位改变时，共振峰也会变化，帮助区分“啊”“衣”“乌”等元音。因此，声道既参与“发了什么音”，也参与“听起来像谁”。

为什么不能把音色直接抽走？

发音内容和个人音色交织在同一条波形里，并没有独立保存成两条轨道。像“s”这样的清辅音还主要来自气流噪声，也不一定有稳定基频。换声需要模型估计哪些信息该保留、怎样生成新的声学细节。

基础资料：NIDCD：人声如何产生、UNSW：声源、声道与发音。

04 / 现在再看 RVC 怎样换声

用来源发音，重建目标声线的波形

假设你说“今天晚上吃什么”，希望转换成 B 的声线。即使让你和 B 用相近的音高与音量说话，频谱和发声细节仍会不同。RVC 要生成这些符合 B 声线的新细节，同时尽量保持你的词句和时间节奏。

来源录音提供

发音和时间线

提取模型估计每一时刻的发音特征；需要保留音高时，还会提取基频 F0 随时间的起伏。这些信息帮助保留原句与旋律。

目标录音教会模型

怎样生成 B 的声音

用 B 的录音训练：给模型发音与音高等条件，让它生成声音，再与 B 的真实录音比较并调整参数。

换声时重新生成

一条新的数字波形

输入你的发音条件，调用学过 B 的模型；目标特征检索可进一步减轻原声线残留，最后输出新音频。

你的录音→发音特征 + 可选音高→目标模型与可选检索→B 声线的新波形

“保留内容、改变音色”是模型努力达到的效果。内容与音色的分离并不完美，因此仍可能出现咬字变差、音色残留或失真。

实现依据：RVC 训练说明、RVC 推理代码。

图 02 / 完整原理

把声音基础、训练和转换连成一个完整过程

沿着图中的 ①—④ 阅读。用“把你说的你好转换成目标声线”这个例子，区分声音是什么、模型怎样学、使用时怎样生成。

  1. 图中 ①

    一条波形包含很多相互关联的特征

    基频影响音高，谐波比例等影响音色；每个谐波也有频率和振幅。真实声音还包含噪声与时间变化，无法只用三个固定数值概括。

  2. 图中 ②

    训练先让模型学到目标声线的生成规律

    给模型目标录音的发音、音高等条件，让它尝试生成声音，与真实录音比较后调整参数。训练后得到模型权重；检索索引则由提取的目标特征建立。

  3. 图中 ③—④

    转换时提取你的线索，再生成新声音

    HuBERT 提供发音特征，音高方法估计高低走势；可选检索参考目标特征。目标生成模型据此输出新波形，词句与节奏尽量延续原输入。

“拆分并复合”要分两层理解

频率分析描述一段声音里哪些频率有多强；RVC 则提取有助于重新发声的条件，再通过学到的规律生成声音。因此“保留内容、改变声线”是一种近似能力，转换可能连带影响咬字、气声与细节。

同一句“你好”，两阶段分工

训练时：目标人物的多段录音用于学习声线。
使用时：你的“你好”提供发音与时间线，已训练模型负责生成目标声线的“你好”。不要求目标人物事先说过这句完整的话，实际泛化效果取决于模型和素材。

01 / TRAINING

训练时，怎样学到目标声音

  1. 01
    清理并切分目标录音

    将清晰的人声切成较短片段，统一采样率，准备与原始波形对应的训练材料。

  2. 02
    提取发音和音高

    用 HuBERT 提取每段录音的发音特征；带 F0 的配置再用音高算法提取 F0。它们与目标录音一起构成训练样本。

  3. 03
    微调生成模型

    从预训练权重继续训练基于 VITS 的生成模型，让它学习怎样根据发音特征、可选的 F0 和说话人信息，合成目标声线波形。

  4. 04
    建立特征索引

    把目标录音提取出的特征放进 FAISS 近邻索引，供之后转换时快速查找。

02 / CONVERSION

换声时，每段音频经历什么

  1. 01
    读入来源声音

    将录音或麦克风声音送入处理流程；长录音会分段，以便逐段转换后衔接。

  2. 02
    提取发音特征

    HuBERT 将来源声音编码为一串特征向量。它们不是文字稿，但包含与发音顺序相关的信息。

  3. 03
    估计并调整音高

    带 F0 的模型用 RMVPE 等算法提取音高；需要升调或降调时，在这一步改变音高轨迹。

  4. 04
    检索目标特征并混合

    启用索引时，当前离线代码寻找 8 个近邻，按距离加权，再按索引比例与来源特征混合；无声辅音等部分可保留更多原特征以减少失真。

  5. 05
    重新合成波形

    生成模型接收混合后的特征、F0 与目标说话人信息，输出新的音频；最后衔接分段并可调整音量、采样率。

这页展示常见的带 F0、启用索引流程。项目也支持不使用 F0 的模型；索引比例设为 0 时可跳过检索，主要依靠训练模型完成转换。

WHY / 01

为什么原话大体保留？

来源录音的发音特征按原有时间顺序进入模型，输入者说的词句、停顿和唱法因此构成转换的基础。RVC 不会替你编写或翻译内容。

WHY / 02

为什么音色会变化？

目标模型学过目标声线怎样发声，检索索引又用目标录音特征纠正来源音色残留。最终波形由模型重新生成，并非简单调高或调低原录音。

LIVE / 03

实时变声怎样连续输出？

麦克风声音按小块进入相同的转换流程；实时界面保留相邻片段的上下文，再用 SOLA 对齐和交叉渐变连接输出，减轻接缝。

效果如何调？索引比例控制目标特征的参与程度；半音变调控制 F0；辅音保护参数控制无声部分保留多少来源特征。参数越大并不必然越好，训练素材质量与原始录音同样重要。

实现依据：训练步骤、索引构建、离线换声代码、实时音频处理代码。

核心模型、权重文件、运行框架、设备分别是什么？

先读上方 A / B / C 三个模型，再向下看共用环境、硬件路线和按需资源。图中的模型与依赖是不同类型的组件。

  1. 先读 A / B / C

    C 是实际生成声音的核心模型

    A 提取发音，B 提取音高，C 根据这些条件生成新声音。目标 .pth 是 C 的权重；RVC 代码定义网络结构。带 F0 的常见模型已包含波形生成部分。

  2. 再读共用环境与设备

    权重通过框架运行，计算由设备执行

    Python、PyTorch、Transformers 等组成运行环境，CPU 或兼容显卡执行计算。按设备选择依赖方案；多个声线通常共用环境和基础模型。

  3. 最后读资源与能力

    基础模型要准备，额外功能再追加资源

    普通换声也需要 HuBERT、所选音高资源和目标声线。训练和分离人声再增加对应底模或分离模型；.index 属于可选数据。

对“后期接入模型”的准确理解

RVC 已写好常见模型的加载与调用流程。用户主要安装匹配环境、下载指定基础模型，并选择一个兼容的目标声线文件；目标声线可获取现成模型，也可自己训练。安装依赖本身不会自动产生想要的声线。

本地是运行位置，多模型协作是实现方式

这套流程可以运行在自己电脑，也可以部署在服务器上。当前以理解能力为目标，可以先不安装；只有要确认声音相似度、清晰度或本机延迟时，才需要实际结果。

核心生成模型在哪里？

目标声线 .pth 就是核心生成模型的权重。 RVC 网络代码定义结构，PyTorch 加载参数并执行计算。HuBERT 与 RMVPE 提供它需要的发音、音高线索。

为何有模型还要安装环境？

模型文件保存学习到的参数；Python、PyTorch、Transformers 等让这些参数能够参与计算。多个声线通常共用基础模型和环境，不必为每个声线重新装一套软件。

哪些只在需要时追加？

训练增加匹配的预训练 G / D 权重和目标录音；人声分离增加对应分离模型；实时换声增加设备与音频路由配置。.index 是由 FAISS 读取的可选特征数据。

依据：官方环境说明、HuBERT、RMVPE、RVC 生成网络。说明日期：2026-09-25；尚未在本项目中部署模型。

REALITY CHECK / 06

使用边界

效果与许可，都需要单独确认

01

素材质量决定上限

低噪、音色统一的录音更重要。官方 FAQ 推荐常规准备 10–50 分钟；极短素材的成功个案不能当作稳定结果。

02

换声不等于重写内容

它主要处理音色。原始录音中的发音、节奏、唱法和噪声，仍会影响转换结果。

03

实时延迟不是固定值

官方报告约 170 毫秒、ASIO 条件下约 90 毫秒；设备、驱动和参数不同，实际体验会变化。

04

声音授权另行处理

仓库代码采用 MIT 许可，不代表自动获得他人声音、训练素材或歌曲的使用权。公开或商用前应确认授权。

依据：官方 FAQ、项目 README、代码许可证。
