# 011 · RD-Agent：自动化数据研发框架

> 研究摘要：RD-Agent 借助外部大模型多次理解资料、提出假设并生成代码，再由框架调度真实运行、评价和反馈。它能把已有论文方法推进到初版实现，也能对有固定数据与指标的任务反复实验；已有量化、数据科学和微调等场景。对我们而言值得留作后期研究工具，等具体问题有基线、评价与预算时再试用。网页数字为模拟示例，未部署 RD-Agent 服务。

## 核心能力

| 能力 | 仓库已有场景 |
| --- | --- |
| 提出与筛选假设 | 基于目标、历史实验和反馈，探索因子、特征、模型或训练方案 |
| 开发与调试 | 把假设变成代码，利用运行错误和测试反馈修复 |
| 执行与评估 | 训练、验证或回测，并记录指标、错误与实验轨迹 |
| 从资料出发 | 从论文或金融报告提取模型、公式与因子描述，推进到实现 |

当前仓库列有量化因子与模型联合优化、Kaggle / 数据科学、论文模型实现，以及基准驱动的大模型微调等入口。不同场景所需数据、依赖与环境各不相同，不能把展示页的模拟结果理解为已复现实验。

## 我们梳理出的两种工作方式

这里的“两种”指工作方式，不是只能用于两个具体业务。第一种是 **Copilot：已有描述 → 代码**。例如找到论文或金融研报后，RD-Agent 读取 PDF，提取模型结构、公式和参数，调用外部大模型生成实现，再用样例输入、形状检查与运行错误修复代码。适合学习算法怎样落地；初版代码可运行不等于已复现论文效果。

第二种是 **Agent：数据 + 目标 + 指标 → 多轮实验**。研究代理根据任务说明、样本或数据概况及历史反馈提出假设；开发代理写特征、模型或训练代码；实际的训练程序读取数据并拟合模型，评估程序计算验证或回测指标；框架记录结果并进入下一轮。模型参数来自训练算法对数据的计算，不是大模型直接写出的。数据科学场景的自定义数据集通常需要训练/测试数据和任务说明，完整评分还需要评价数据或评分程序。

官方还从另一维度区分 **模型实现** 与 **数据构建**：前者关注模型结构和代码，后者关注数据、特征与因子。Copilot / Agent 回答“谁决定下一步”，模型 / 数据回答“改进什么”，金融 / 数据科学 / 微调回答“在哪个领域”。部分循环提供人工修改假设或反馈的接口；并行探索和图形界面是调度与操作方式，不另算主要角色。

**适用前提**：目标能转成可执行任务和可信评价。量化、数据科学、论文模型实现与大模型微调等已有场景可直接从官方入口探索；3D 人物、语音或物理仿真需要先定义输入输出、领域运行流程与评价方法，再判断是否值得自定义场景适配。RD-Agent 不保证多次迭代就达到期望，也不是任意论文到完整产品的转换器。

详见网页的[两种路径和场景目录](../../docs/projects/011-rd-agent/index.html#paths)，以及[官方通用模型文档](https://rdagent.readthedocs.io/en/latest/scens/model_copilot_general.html)、[数据科学文档](https://rdagent.readthedocs.io/en/latest/scens/data_science.html)。

## 底层技术原理

任务与数据 → Researcher 提出假设 → 生成实验任务 → Developer 编写与修复代码 → 执行器训练 / 测试 / 回测 → 评价器生成指标与反馈 → 记录轨迹 → 下一轮假设。

核心抽象包括 Scenario、HypothesisGen、Hypothesis2Experiment、Developer、Experiment2Feedback 与 RDLoop。Co-STEER 将历史实现与反馈作为可检索经验，用于任务安排和代码修复；多路线探索允许比较不同方案。这里的经验积累主要是实验记录与检索，不等于每轮更新底层大语言模型参数。微调场景是单独的研发任务。

参考：[整体技术报告](https://arxiv.org/abs/2505.14738)、[Co-STEER 论文](https://arxiv.org/abs/2407.18690)、[循环代码](https://github.com/microsoft/RD-Agent/blob/main/rdagent/components/workflow/rd_loop.py)。

## 使用场景与对我的价值

- 语音工具链：可先为 [003 Voicebox](../003-voicebox/README.md) 和 [005 WhisperLiveKit](../005-whisperlivekit/README.md) 建立固定中文测试集，以词错率、延迟、资源消耗为指标，之后再考虑自动搜索数据处理或模型方案。这是可扩展方向，尚未接入。
- 量化或其他机器学习研究：若有可重复运行的数据集、基线和评价指标，可减少人工重复尝试，保留每轮实验依据。
- 内容创作工具：[010 Jellyfish](../010-jellyfish/README.md)、[008 video-use](../008-video-use/README.md) 的耗时、失败率可量化；镜头和叙事质量较难可靠自动评分，需设计人工审核。

最现实的起点是固定一批有人工转写的中文音频，先建立基线，比较不同方案的词错率、延迟和成本。是否值得接入整个框架，取决于实验改进是否超过接入和运行成本。

## 为什么论文代码还不是完整 3D 人物

论文常只解决一个研究问题，例如从单张图像重建几何，或为已有网格生成纹理。RD-Agent 的 Copilot 可以尝试按论文描述写模型代码并运行基本检查，但完整的 3D 人物产物还需要匹配的数据与权重、推理环境、几何与纹理后处理、骨骼/动画、导出格式以及人工或自动质量评价。单篇论文未必覆盖这些环节，上游也没有开箱即用的完整 3D 人物流程。

因此更可行的顺序是：先明确输入（文字、单图还是多视图）与目标输出（静态模型还是可动画角色）；再寻找对应论文及作者的公开实现与权重，验证它能生成哪一部分；最后才考虑把需要反复调参或改代码的部分接入 RD-Agent。若无法自动执行和评价，迭代循环缺少可靠反馈。

## 何时回顾与重新尝试

**建议保留并后期回顾。** 当前若只是理解论文，先用大模型分解研究问题、方法、公式、数据和实验，再对照论文与公开代码；需要验证实现时，可尝试 Copilot。若目标是做完整 3D 人物，应优先完成上述产物流程的选型。为了单次阅读论文搭建整套 RD-Agent 环境通常投入偏高。

当出现可重复的研究任务时，再做一个小试验：明确输入输出、固定数据与验证集、可运行基线、客观指标、时间/算力/API 预算及人工验收标准。语音工具链是较清晰的候选：用固定中文音频比较词错率、延迟和成本，让系统尝试少量改进，比较收益与接入成本。若结果稳定可复现，再决定是否扩展到更复杂的 3D 或内容任务。

**判断边界：** 可运行代码不等于忠实复现论文；训练得到的分数也不自动说明模型有实际价值。需要检查数据切分、模型输出、资源成本与人工质量。

## 可扩展方向

1. 实现自己的场景适配器：数据说明、实验任务、执行环境、评价器。
2. 增加多目标与时间外评估：质量、延迟、成本、稳定性、数据泄漏检查。
3. 将团队历史实验、失败原因和人工判断纳入知识检索与下一轮假设。

这些是针对本仓库项目组合的建议，并非 RD-Agent 已提供的跨项目集成。
